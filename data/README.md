# 데이터

원본 사진은 용량과 개인정보 문제로 저장소에 올리지 않고 팀 공유 드라이브에 보관합니다. 로컬에서는 `data/raw/`에 두면 `.gitignore`로 제외됩니다. 정답 CSV만 `data/labels/`에 올립니다.

## 촬영 가이드

| 항목 | 기본 조건 | 확장 조건 |
| --- | --- | --- |
| 배경 | 단색 (고정) | 밝은 단색 / 어두운 단색 |
| 조명 | 기본 | 기본 / 밝음 / 어두움 |
| 거리·각도 | 고정 거리, 수직 촬영 | 동일 |
| 배치 | 동전끼리 겹치지 않음, 앞·뒷면·회전·혼합 | 동일 |
| 수량 | 100장 이상 (조정용 60 / 테스트 40) | 조건별 10장, 60장 이상 |

파일 이름: `<조건>_<묶음>_<번호>.jpg` (예: `base_g03_012.jpg`, `dark-bg_bright_g01_004.jpg`)

## 현재 정답 CSV 형식 (사진 단위)

`data/labels/coins.csv`는 사진 한 장당 한 줄이며, 기본 조건 사진 100장의
종류별 개수와 총금액을 기록합니다. 인코딩은 UTF-8이며 BOM이 있어도 읽을 수 있습니다.

| 열 | 설명 | 예시 |
| --- | --- | --- |
| `파일` | 원본 사진 파일 이름 (전체 데이터에서 중복 금지) | `single_001.jpg` |
| `10원`, `50원`, `100원`, `500원` | 해당 종류의 동전 개수 (0 이상의 정수) | `1`, `0`, `0`, `0` |
| `동전 수` | 종류별 개수의 합 | `1` |
| `총액` | 금액 × 개수의 합 (원) | `10` |

```csv
파일,10원,50원,100원,500원,동전 수,총액
single_001.jpg,1,0,0,0,1,10
```

이 형식은 `eval/evaluate_counts.py`에서 지원합니다. 총금액 일치율과 종류별 개수
완전일치율을 계산할 수 있습니다. 동전별 위치 정답이 없으므로 검출률·분류 정확도는
개수 기반 근사치이며, 검출 개수가 같아도 실제 동전 위치를 정확히 찾았다고 보장하지 않습니다.

`split`과 배치 유형은 정답 CSV에 포함되어 있지 않습니다. 평가 스크립트를 사용할 때는
`image`, `split`, `layout` 열이 있는 별도 매니페스트를 `--manifest`로 전달해야 합니다.
현재 저장소에는 매니페스트가 포함되어 있지 않습니다. `eval/make_preds.py`도
`image`, `split` 열이 필요하므로, 현재 `coins.csv`를 그대로 `--labels`에 전달할 수 없습니다.
자세한 사용법은 [평가 가이드](../eval/README.md)를 참고합니다.

## 동전별 위치 정답 형식 (추후 수집)

초기 가이드에서 계획한 형식은 동전 한 개당 한 줄입니다. 현재 `coins.csv`에는
아래 위치·분할·묶음 정보가 없으며, 사진 단위 개수만으로 이를 복원할 수 없습니다.
추후 위치 정답을 수집하면 사진 단위 CSV와 별도 파일로 관리하고,
`eval/evaluate.py`의 `--labels`로 전달합니다.

| 열 | 설명 | 예시 |
| --- | --- | --- |
| `image` | 파일 이름 | `base_g03_012.jpg` |
| `split` | `tune` / `test` / `ext` | `test` |
| `group` | 연속 촬영 묶음 ID (split 간 중복 금지) | `g03` |
| `condition` | `base` 또는 `<배경>_<조명>` | `base` |
| `x`, `y`, `r` | 동전 중심 좌표와 반지름 (픽셀) | `412,280,57` |
| `value` | 금액 (10/50/100/500) | `100` |

이 형식의 이미지별 총금액은 `value`를 합산해 구합니다.
`group`은 연속 촬영 묶음이며, 같은 묶음이 tune과 test에 동시에 들어가지 않도록 관리합니다.
